# Engineering Workflow

## Repository Analysis

Before making changes:

1. Use codebase-recon
2. Understand architecture
3. Identify impacted files
4. Identify risks

## Planning

Before implementation:

1. Use create-plan
2. Create implementation plan
3. Present plan
4. Wait for approval

## Coding Rules

Follow karpathy-guidelines.

- Prefer smallest working change
- Avoid unnecessary abstractions
- Avoid speculative features
- Avoid unrelated refactors
- Touch only required files
- Match existing code style and architecture

## Verification

Before completion:

- Run tests when available
- Run lint when available
- Run build when available

## Review

Use codex-review.

Report:

- Files changed
- Verification performed
- Risks found
- Remaining issues

## Communication

Before coding:

- State assumptions
- State scope
- State verification strategy

After coding:

- Summarize changes
- Summarize validation
- Highlight risks
